# CabGo - Full-Stack Ride Booking Platform

CabGo is an urban mobility and ride-hailing web platform built directly around high-fidelity designs generated by Stitch. It provides complete end-to-end functionality including ride searches, dynamic route and vehicle selection, itemized payments, live GPS telemetry tracking, passenger hubs, booking histories, and driver consoles with JWT security and MSSQL persistence.

---

## Architecture & Technology Stack

- **Frontend**:
  - React 18, Vite
  - Tailwind CSS (extended with Stitch design system tokens: palette, typography, elevation, rounded geometry)
  - React Router v6
  - Axios with JWT request interceptor & 401 redirect
  - Material Symbols Outlined & Google Fonts (Inter + Plus Jakarta Sans)

- **Backend**:
  - Spring Boot 3.3.4
  - Java 17+ (Java 24 LTS compatible)
  - Spring Security 6 with stateless JWT Bearer filter chain
  - Spring Data JPA
  - Microsoft SQL Server (MSSQL) Driver (`com.microsoft.sqlserver.jdbc.SQLServerDriver`)
  - Flyway database migration engine (`V1__init_schema.sql`, `V2__seed_data.sql`)

- **Database**:
  - Microsoft SQL Server (`MSSQL`)
  - Flyway migration scripts under `database/migrations/` and `backend/src/main/resources/db/migration/`

## Getting Started

### 1. Database Configuration (MSSQL Server)

The application uses Microsoft SQL Server (`MSSQL`) with Flyway migrations managing the database schema automatically on boot.

1. Ensure your local Microsoft SQL Server instance or Azure SQL is running (default port `1433`).
2. Create an empty database:
   ```sql
   CREATE DATABASE cabgo_db;
   ```
3. Open `backend/src/main/resources/application.properties` and verify or adjust connection parameters:
   ```properties
   spring.datasource.url=jdbc:sqlserver://localhost:1433;databaseName=cabgo_db;encrypt=true;trustServerCertificate=true;sendStringParametersAsUnicode=true
   spring.datasource.driver-class-name=com.microsoft.sqlserver.jdbc.SQLServerDriver
   spring.datasource.username=sa
   spring.datasource.password=YourStrong@Passw0rd
   ```
   *Tip: You can also override these via environment variables:*
   ```powershell
   $env:DB_URL="jdbc:sqlserver://localhost:1433;databaseName=cabgo_db;encrypt=true;trustServerCertificate=true"
   $env:DB_USERNAME="sa"
   $env:DB_PASSWORD="YourPassword"
   ```

When the Spring Boot backend starts, Flyway will automatically run `V1__init_schema.sql` and `V2__seed_data.sql`.

---

### 2. Running the Backend

Open a terminal in the `backend/` directory:

```bash
# Using the bundled Maven Wrapper (Windows):
.\mvnw.cmd spring-boot:run

# Using the bundled Maven Wrapper (Linux / macOS):
./mvnw spring-boot:run

# Or using global Maven if installed:
mvn spring-boot:run

# Optional: Run with zero-config in-memory H2 mode (instant testing without local MSSQL):
.\mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=h2
```

The backend server will launch on `http://localhost:8088`.

---

### 3. Running the Frontend

Open a terminal in the `frontend/` directory:

```bash
# Install dependencies:
npm install

# Start local development server:
npm run dev
```

The frontend will start at `http://localhost:5173`.

### 4. Google Maps & Live Routing Telemetry Configuration (Optional)

The application includes full Google Maps integration with route polylines, live traffic, and dynamic driving distance calculations.

To use your own Google Cloud API Key:
1. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
2. Set your key:
   ```env
   VITE_GOOGLE_MAPS_API_KEY=AIzaSy...
   ```
   *(Ensure `Maps JavaScript API`, `Directions API`, and `Places API` are enabled in your Google Cloud Console)*
3. **Alternative**: You can also enter or update your key directly inside the app by clicking the **"🔑 Google Key"** button on the map UI!
4. **Smart Fallback**: If no key is set or quota is pending, CabGo automatically uses road-accurate driving telemetry and real-time interactive mapping without crashing.

## API Endpoints Overview

- **Auth**:
  - `POST /api/auth/login`: Authenticate with email/phone & password -> returns JWT token and user info
  - `POST /api/auth/register`: Register as passenger or driver partner
- **Vehicles**:
  - `GET /api/vehicles`: List all available vehicle categories (Mini, Sedan Prime, SUV, EV Prime)
  - `GET /api/vehicles/{code}`: Get vehicle tier details & base rates
- **Bookings**:
  - `POST /api/bookings`: Create and confirm ride booking (authenticated)
  - `GET /api/bookings/{id}`: Get booking by ID
  - `GET /api/bookings/ref/{ref}`: Get booking by reference (e.g. `CG-849201`)
  - `GET /api/bookings/my-bookings`: List current user's trips (authenticated)
  - `PATCH /api/bookings/{id}/status`: Update ride status (`DRIVER_ARRIVING`, `IN_PROGRESS` with OTP, `COMPLETED`)
  - `POST /api/bookings/{id}/cancel`: Cancel a ride
- **Drivers**:
  - `GET /api/drivers/me`: Get current driver partner profile
  - `PATCH /api/drivers/status`: Update online/offline state & GPS coordinates
  - `GET /api/drivers/incoming-requests`: View dispatch requests & assigned trips
- **Payments**:
  - `POST /api/payments/process`: Process payment transaction (UPI, Card, Wallet, Net Banking, Cash)
  - `GET /api/payments/booking/{bookingId}`: Get payment confirmation
- **Users**:
  - `GET /api/users/me`: Current profile data & wallet balance
  - `GET /api/users/saved-locations`: List saved favorite addresses (Home, Work, Airport)
